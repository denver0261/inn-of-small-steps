# 0005: M1 Expo app

Date: 2026-11-27
Status: accepted (the flagged choices are open for the players to change)

## Context

The third M1 slice (see [0003](0003-m1-habit-rules.md)) is the iPhone app: sign-in for two players, day-one setup, habits with goals, logging, the shared chore list and consistency rates. The Apple Health import is the fourth slice.

## Decisions

**Stack.** Expo SDK 58 with Expo Router, React Native 0.88, React 19.3 and supabase-js 2.119. Every version is at least 14 days old (pnpm's `minimumReleaseAge`). The app is a development build (`pnpm app` runs `expo run:ios`), not Expo Go, because HealthKit needs native code. The generated `ios/` folder is git-ignored and rebuilt from `app.json`.

**Code layout.**
- `app/`: screens. Day one runs Arrive → House (rent it, or join by invite code) → Path → Starting habits. Then come the tabs: Today, Habits, Chores, House.
- `src/data/rows.ts`: the only place database rows become engine types. Every row is parsed with the shared zod schemas, so a bad row fails there.
- `src/data/api.ts`: every Supabase call.
- `src/game/board.ts`: the Today screen's numbers, computed by engine functions (`consistencyRate`, `weekProgress`, `habitSlots`). The app does no game math of its own.
- `packages/content/src/starterHabits.ts`: the design's core habits (biking, lifting, eating well, tidying, prescribed PT 3x a week) as day-one presets.

**Sign-in is a 6-digit code by email**, with no passwords to keep. The local stack shows the code in Mailpit (http://127.0.0.1:54324). The online projects need the same email template, `supabase/templates/code.html`, which `supabase config push` sends up.

**Logging.** A tap logs a full or a tiny session for today. Taps can be undone until the day closes (the database refuses after that). Once a day goal is met for today, its Done and Tiny buttons go away (`doneForToday` in `src/game/board.ts`); weekly goals keep them, since two sessions in one day both count. Habits that come from Apple Health show "Comes in from Apple Health" and have no tap button. Each player's Today screen also lists what their partner did today, by habit name only.

**Chores.** The list groups due chores by room, most overdue first, and shows what's coming up with who last did it. Checking a chore off logs it to the player's Home habit.

**Flagged: choices the design leaves open.**

| Question | M1 answer | Why |
| --- | --- | --- |
| How do you sign in? | a 6-digit email code | No passwords to keep, and no Apple Developer account needed yet. Sign in with Apple can be added once there is one. |
| Which habit does a chore log to? | your first Home-domain habit (Tidying, if you took the preset) | The design says chores count as a Home log; with no Home habit, the app asks you to add one. |
| Bundle id | `dev.innofsmallsteps.app` | A placeholder until the Apple Developer account exists. |

**Known gaps, on purpose:**
- **Online only for now.** The design calls for offline logging with SQLite sync. M1 talks to Supabase directly; offline sync waits until the playtest shows it's needed.
- **Some rules are checked in the app only.** The 7-day free path switch and the habit slot limit are checked by the app, not the database. They're honesty rules between two players, not security.
- **Chore check-off is two writes** (mark the chore done, then add the log). If the second write fails, the chore shows done without a log.
- **No pause screen yet.** The engine and database support pauses. The screen for them comes with M2, where pauses start to matter for XP.

**Checked in the Simulator** (iPhone 18 Pro, local Supabase): email-code sign-in, Arrive → rent the house → path → starter habits, Done / Tiny / Undo on Today, a goal change on Habits, a room and an invite on House, adding a chore and checking it off (it logs to Tidying), and the two-player path. A second player joined through the invite link, each Today showed the other's done habits, and a row-level-security check confirmed neither can read the other's workouts. That pass fixed three UI bugs: picked weekdays never showed as selected (Habits and Chores), the new-room field rendered squashed, and Done/Tiny stayed visible after a day goal was met.

## Consequences

- `pnpm check` also typechecks the app and runs its unit tests (`apps/mobile/test`).
- Running the app locally takes `pnpm exec supabase start`, then `pnpm db:env`, then `pnpm app`.
